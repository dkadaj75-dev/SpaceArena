# MAP OVERHAUL — props with real collision, the Map Editor, and Lunar Rift (5v5 CTF)

**Status: BINDING SPEC** (owner 2026-08-12). This supersedes the "a map is bounds + rocks +
spawns" model for arenas that opt in. Companion docs: `MAPS-AND-SKYBOXES.md` (still valid for
bubble arenas), `FLIGHT.md`, `BUBBLE.md`.

Three deliverables, in dependency order:

1. **Props** — a new content type: GLB-rendered static geometry with **trimesh collision**
   shared by server sim, client prediction, projectiles, line of sight, and bots.
2. **Map Editor** — extend the existing `MapEditor` tab into a full placement editor:
   asset browser, prop placement with gizmos, flag bases, nav graph, GLB import, playtest.
3. **Lunar Rift** — a point-symmetric 5v5 CTF arena of craters, slot canyons and tunnels,
   generated by a repeatable tool. The canyon tops are the map limit (no bubble).

Everything is data. No per-map code.

---

## 1. Design rules (unchanged, binding)

- NOTHING per-ship or per-map hardcoded; schemas + tools must cover new properties.
- `shared/` stays environment-agnostic: zod-only, **no fs, no fetch, no Babylon**. All
  collision data rides **inside configs** (see §2.2) through the existing `ConfigLoader`.
- Determinism: sim + bots byte-identical for a given (configs, seed). No `Math.random`,
  no per-host float paths. BVH construction and queries are plain float64 arithmetic.
- The wire does not change. Arenas are config-referenced, never replicated
  (`server/src/rooms/state/ArenaState.ts:6-9`). Static props are invisible to the protocol.
- Working agents: never `git commit/checkout/reset/stash`, never delete data dirs, never
  revert files you did not change. The tree carries other uncommitted work.

## 2. Props — content type and collision data

### 2.1 `prop.*` config (new type)

`shared/src/schemas/prop.ts`:

```ts
propSchema = z.object({
  ...baseShape("prop"),
  /** Editor grouping + placement behaviour. Sim ignores it. */
  category: z.enum(["terrain", "structure", "rock", "decor"]),
  /** Ship-vs-prop impact damage at >= tuning.impactSpeedThreshold closing speed. 0 = harmless scenery. */
  impactDamage: z.number().nonnegative().default(0),
  /** Standard render recipe; recipe "model.static" means GLB-only (no procedural fallback). */
  render: renderRecipe.extend({
    /** Optional authored LOD ladder, nearest first: [{model, distance}]. distance in world units for scale=1. */
    lods: z.array(z.object({ model: z.string().min(1), distance: z.number().positive() })).optional(),
  }),
  /** Trimesh collision, baked (§2.2). Omitted => prop is non-solid decor. */
  collision: z.object({
    /** base64 of little-endian Float32Array, xyz triplets, local space. */
    positions: z.string().min(1),
    /** base64 of little-endian Uint32Array, triangle indices. */
    indices: z.string().min(1),
    /** AABB of the collision mesh in local space, precomputed. */
    bounds: z.object({ min: vec3required, max: vec3required }),
  }).optional(),
});
```

Register per the exhaustive-record checklist: `schemas/index.ts` (CONFIG_SCHEMAS + AnyConfig +
`collectReferences` — arena placements reference `prop`), `content/configPath.ts`
(`prop: "props"`), `client/src/editor/applicationScope.ts` (`next-match`),
`SchemaFormGen.ts` REFERENCE_TYPES (`propId: "prop"`). Content lives in `content/props/*.json`
+ `content/props/*.glb`.

Size guard (schema `superRefine`): `indices` ≤ **150k triangles** decoded; positions/indices
base64 well-formed and length-consistent (multiple of 3). Fail loud at validate:content.

### 2.2 Why collision-in-config (do not "improve" this)

The server never parses GLB and `shared` never loads files; packs are JSON-only
(`shared/src/content/pack.ts:65`). Baking collision into the prop JSON keeps: pack
export/import/rollback working unchanged, in-flight matches pinned to a consistent pack,
client prediction and offline bots reading the *same* bytes the server reads, and zero new
loader abstractions. The GLB is **render-only**; `COL_*` meshes inside a GLB are consumed
only by bake-time tooling (generator tool, editor upload endpoint), never at runtime.

`shared/src/collision/base64.ts`: tiny dependency-free base64 encode/decode to
`Float32Array`/`Uint32Array` (no `Buffer`, no `atob`). Both hosts share it.

```ts
propPlacements: z.array(z.object({

```

### 2.4 StaticWorld (shared/src/collision/)

Built once per sim/session from `(arena.propPlacements, prop configs)`:

- `bvh.ts` — static AABB tree per prop config (median split, leaf ≤ 8 tris), built from the
  decoded arrays, cached per config id (WeakMap on the config object is fine — configs are
  frozen + replaced wholesale).
- `staticWorld.ts` — placements with precomputed world transform (pos, rot 3×3 from YXZ
  euler, uniform scale) + inverse. Queries transform into local space, run the BVH, transform
  back (normal via rotation matrix; distances × scale):
  - `raycast(from, to) -> { t, point, normal, placementIndex } | null` (nearest along segment)
  - `sphereContact(center, radius) -> { depth, normal, point, placementIndex } | null` (deepest contact; closest-point-on-triangle)
  - `heightBelow(pos, maxDrop) -> { y, normal } | null` (downward raycast helper for bots/editor)
- All queries early-out on placement world AABBs (linear scan; arenas carry ≤ ~40 placements).

`World` (shared/src/sim/World.ts) owns `staticWorld: StaticWorld` (empty when no placements).
It is **not** an entity, not in the spatial hash, not in snapshots.

### 2.5 Sim integration (exact seams)

- **Ship vs prop** — new pass in `CollisionSystem` (`shared/src/sim/systems/CollisionSystem.ts`),
  after ship-vs-asteroid, before boundary: up to 2 iterations of
  `staticWorld.sphereContact(pos, collider.radius)` → push out along normal by depth, cancel
  inward normal velocity (no restitution — same contract as asteroids, pinned by
  `Regression.test.ts` "collision grind death"). Impact damage: same rules/cooldown as
  asteroids (`tuning.impactSpeedThreshold` ≥ 6 closing speed, `impactDamageCooldown`,
  pairKey ship×(0x200000 + placementIndex) to avoid asteroid key collisions), damage =
  prop config `impactDamage`.
- **Projectiles** — `ProjectileSystem.findHit` (`ProjectileSystem.ts:189-238`): also test
  `staticWorld.raycast(from, to)`; nearest hit wins; a prop hit destroys the projectile,
  damages nothing.
- **Beams/nose rays** — `CombatSystem.raycastNose` (`CombatSystem.ts:226-275`): prop hit
  blocks like an asteroid (returns isStatic hit; beams stop, no damage banked).
- **LoS** — `shared/src/sim/los.ts`: `hasLineOfSight` and `hasLineOfSightBetween` also test
  `world.staticWorld.raycast`. `hasLineOfSightAmong(a, b, blockers, staticWorld?)` gains an
  optional trailing param (bots/client pass the one they hold; absent = sphere-only, existing
  tests unchanged).
- **Targeting** — unchanged (locks warm through rock today; canyon play makes lock-through-wall
  worse, but changing it moves combat balance — defer, note in §10 open questions).
- **Boundary "box"** — see §3.

### 2.6 Client prediction (required, not optional)

Canyon flight means *sustained* wall/floor contact; server-only push-out would snap the
predictor every contact tick (`NetGameSession.correctPrediction`, SNAP_DISTANCE 3).

New shared helper `resolveStaticStep(world | {staticWorld, bounds, rule, tuning}, state)` that
applies, in order: prop sphere contacts (§2.5 semantics) then box-bounds resolution (§3
semantics, including the damageAndBounce **nose reflection** via the existing transportUp/
spellAttitude path). `CollisionSystem` calls it for ships; `NetGameSession` prediction calls
the same function after `flightStep` (`NetGameSession.ts:702-712`). `steering.test.ts:53`
(flightStep ⇄ NavigationSystem parity) is untouched because flightStep itself does not change.
Dynamic obstacles (asteroids, ships) stay server-only — rare snaps, as today.

`onlineLoop.test.ts` gains a canyon case: a ship grinding along a prop wall for 3 s with held
throttle must produce **zero snaps** and residual < 1.

## 3. Bounds shape "box" — the canyon limit

`arenaBounds` union gains:

```ts
z.object({ shape: z.literal("box"),
  width: z.number().positive(),      // x extent, centered on 0
  height: z.number().positive(),     // z extent, centered on 0 (legacy naming, matches rect)
  floorY: z.number(),                // absolute kill-floor (safety net below terrain)
  ceilingY: z.number(),              // THE canyon-top limit
}).refine(ceilingY > floorY)
```

- Sim (`resolveBoundary`): resolve **all** violated faces in one tick (fix rect's one-face-
  per-tick wedging for the new shape; leave legacy `rect` alone). Ceiling + walls + floor all
  apply `gamemode.boundaryRule` (Lunar Rift ships `damageAndBounce`, so the ceiling shoves you
  back down with the existing attitude reflection).
- Projectile cull: outside box + `projectileBoundsMargin`.
- Wire checks: `arenaWireBoundsIssues`/`arenaWireEnvelopeIssues` handle "box" (half extents +
  |floorY|/|ceilingY| + margin ≤ 3276.7).
- Spawn-inside check: schema superRefine covers box.
- **Render** (`SceneBuilder.buildBounds`): hex-shader **ceiling plane** at `ceilingY` (reuse
  `BOUNDARY_FRAGMENT` material on a ground-oriented quad, same proximity glow driven by
  vertical distance) + 4 wall quads with the same material driven by lateral distance.
  `updatePlayerPosition` computes distance-to-nearest-face for the warn notification.
  The rect orange-stub path stays as-is.
- Bots: see §6.

## 4. Rendering props (client)

- `SceneBuilder.buildProps()` beside the existing terrain path: for each placement,
  `AssetRegistry.ensureModel` + `createInstance`, parented under `arenaRoot` (free
  freeze/hide/dispose). Position/rotation(YXZ)/uniform scale from the placement.
  Instances share masters (repeated rocks are cheap).
- `finalizeModel` (`AssetRegistry.ts:619-668`) gains a **no-merge mode** for props whose GLB
  has multiple top-level meshes (terrain chunks must cull per-chunk): return a parent
  `TransformNode` with the parts as children; still drop `COL_*` meshes, still bake
  scale/rotation, still apply the PBR clamp. (Prop GLBs are authored matte — the clamp is a
  no-op for them in practice.)
- **Generic LOD**: `render.lods` ladder — `addLODLevel(distance_i × scale, lodMesh_i)` per
  part, nearest-first, no cull level for `category: "terrain"` props (terrain never
  disappears). Falls back gracefully when `quality.scene.terrain?.lodBias` (new optional
  block: `{ lodBias?: number, enabled?: boolean }`) scales distances; `low` tier may author
  `lodBias 0.5`.
- Preload: `arenaModelRenders` (`client/src/core/assetPreload.ts:25-44`) also walks
  `propPlacements` (base model + every lods[] model) so match start has no pop-in.
- Editor pickability: prop instances built by the *editor preview* set `isPickable = true`;
  match-time instances stay `false`.

## 5. Map Editor (extend `client/src/editor/MapEditor.ts`)

Keep the existing shape: live scene, `GizmoManager`, save via `/__editor/save`. Add:

1. **Layers panel**: Asteroids / Props / Spawns / Flag bases / Nav graph / Bounds. Each row:
   visibility eye + lock. Terrain-category props default locked (`placement.locked`).
2. **Asset browser**: every `prop.*` and `asteroid.*` config (name, category, tri count) +
   "Import GLB…" (§5.1). Click-to-place: raycast the pointer against **prop meshes first**,

3. **Transforms**: translate/rotate/scale gizmos (rotate = full YXZ; scale = uniform only —
   clamp the gizmo). Snap toggles (1u / 15°). Duplicate (Ctrl+D) with placement twin offset.
   **Mirror-place mode**: while active, every placement/edit auto-maintains the 180° twin
   (`(-x, y, -z)`, rotation `y+π`) — the tool that keeps the map e-sport-symmetric.
4. **Spawn points + flag bases**: markers become pickable/gizmo-editable (spawns: position +
   heading via rotate gizmo; flags: position + radius ring). Flag bases get a visible ring +
   pole marker in the editor (SceneBuilder renders none today).
5. **Nav graph** (§6): place nodes (pickable spheres), link/unlink (select two, L), lane paint
   shows as tube polylines. Saved into the arena config.
6. **Bounds editing**: form fields (SchemaFormGen section) + a translucent ceiling preview.
7. **Playtest**: button → `EditorHost.launchPlaytest(arenaId, gamemodeId)` (new host method in
   `EditorShell.ts:21-44` / `main.ts` modeled on `startTutorialMatch`, `main.ts:872-904`):
   offline `GameSession` with bots on the edited arena, Esc returns to the editor.
8. **Camera**: raise editor orbit `upperRadiusLimit` to fit 640-unit maps; add pan-to-cursor
   focus (F frames selection, like ShipManager.focusCamera).

### 5.1 GLB import (dev-only endpoint)

`POST /__editor/upload-model` in the vite `contentPipelinePlugin` (`client/vite.config.ts`),
sibling of `/__editor/save`:

- body: raw octet-stream; query: `?path=props/<name>.glb` (segment-validated like
  `contentPathProblem`, `.glb` only, ≤ 32 MB, path-traversal guarded).
- server side (Node): parse the GLB (tooling parser, §7), find `COL_*` meshes → bake a
  `collision` block; none found → collision from the visual mesh if ≤ 150k tris, else bbox
  prompt (return 422 with reason, editor offers "import as decor / bake bbox").
- writes the .glb under `content/props/`, responds with a **draft prop config JSON** the
  editor opens pre-filled (category, render.model, collision, bounds) for the user to save
  normally (which manifests it via `persistEditorConfig`).
- `GET /__editor/list-models` already exists for discovery; no change.

Bundle-budget note: all new editor code must stay behind the lazy `import()` and the
`/__editor/` marker rules (`tools/bundle-budget.ts` gates).

## 6. Bots in canyons

The minimum for credible 5v5 CTF in slot canyons:

1. **StaticWorld awareness**: `BotDriver` env gains `staticWorld` (passed from `ArenaRoom`
   backfill and `GameSession` bot construction — same seam as `arenaBounds`/`floorY` today,
   `ArenaRoom.ts:568-571`). `hasLineOfSightAmong` callers pass it (context.ts, BotDriver,
   behaviors.breakLoS, botOverlayModel).
2. **Probes**: `noseBlocker` corridor test also raycasts staticWorld (blocked distance →
   same avoid vocabulary). Recovery (`recovery.ts`): `restSurfaces` gains nearest static
   contact (from `sphereContact` at own radius + margin) and the **box shell** (walls +
   ceiling + kill-floor as planes); `arenaShellSurface` handles `shape: "box"`. Floor guard:
   when bounds are box, `env.floorY` is replaced by `staticWorld.heightBelow(pos, 40)` — guard
   against *terrain*, not a global plane (cache per decision tick; it runs at bot cadence, not
   sim cadence).
3. **Nav graph**: arena config gains

   ```ts
   navGraph: z.object({
     nodes: z.array(z.object({ id: z.string(), position: vec3, /** wide-open hub (crater) */ hub: z.boolean().optional() })),
     links: z.array(z.tuple([z.string(), z.string()])),   // bidirectional, must reference nodes
   }).optional(),
   ```

   Shared `shared/src/bots/navRoute.ts`: builds adjacency + all-pairs next-hop (Floyd–Warshall
   at construction; graphs are ≤ 64 nodes). API:
   `nextWaypoint(from: Vec3, goal: Vec3) -> Vec3 | null` — nearest node to `from` with LoS
   (staticWorld raycast), nearest node to `goal`, walk next-hop; returns `null` when the
   direct segment `from→goal` is already clear (then fly straight, as today).
4. **Use it in `ctfBehavior.chooseJob`**: striker/carrier/escort aim points route through
   `nextWaypoint` when the direct segment is blocked. Interceptor/warden keep direct pursuit
   (their targets are usually near). `commitStuckCarrier`'s "up and sideways" fudge
   (`BotDriver.ts:1001`) becomes "toward current waypoint" when a route exists.
5. **Fix the `visualRadius` bug**: `ArenaRoom.ts:571` / `GameSession.ts:245,379` pass
   `render.modelScale` (a scale factor) where recovery expects a world-unit extent; pass the
   resolved hull visual extent instead (ship collider radius is the honest lower bound; use
   `max(collider.radius, modelScale/2)` if nothing better exists — justify in code comment).
   Re-tune recovery tests that pinned the degenerate behaviour if any.
6. **Acceptance** (gate, not vibes): `tools/bot-ctf-review.ts` on `arena.lunar-rift` seeds
   11/42/73 — every seed finishes with ≥ 1 capture, zero stuck-bot reports, zero
   out-of-bounds deaths. `CtfBots.test.ts` gets a lunar-rift capture test with a fixed bound.

## 7. The generator tool — `tools/generate-lunar-rift.ts`

Deterministic, parameterized, re-runnable: layout data → terrain GLB chunks + prop configs +
the arena JSON (spawns, flags, navGraph, bounds, placements). Re-running with the same params
is byte-stable (seeded murmur/fBm only — remember the weak-hash lesson: murmur required).

New devDependencies (tools only): `@gltf-transform/core` (GLB write), `manifold-3d` (tunnel
CSG). Node ≥ 18. Nothing in shared/client/server gains deps.

Pipeline:

1. **Layout DSL** (in-file data): craters (center, radius, floorY, rimHeight), lanes (spline
   points, width, floor undulation), tunnels (segment, radius), all authored for one side —
   the tool **generates the 180° twin automatically**. Symmetry is by construction.
2. **Heightfield SDF**: base highland `y = H_top(80)` with fBm relief; carve lanes (smooth-min
   channels, noise-perturbed walls with strata shelves), crater bowls (rim lip + ejecta
   noise), blend radii; floor detail (regolith undulation, talus at wall bases). Domain-warped
   fBm; slope-driven detail amplitude.
3. **Mesh**: adaptive grid per 160×160-unit chunk (4×4 chunks over 640×640): dense (≈1.25u)
   where playable, coarse (≈5u) on highland tops. Target ≤ 250k tris LOD0 total. LOD1 =
   regenerated at ¼ density (≤ 80k total). Skirts on chunk borders (hide LOD cracks).
4. **Tunnels**: straight bores, Ø 15: CSG-subtract noise-displaced cylinders from the chunk
   solids (manifold-3d), both visual + collision. Portal rims get a torus lip so entrances
   read from afar.
5. **Collision mesh**: separate ≈2.5u-grid mesh per chunk, clipped to reachable space
   (y ≤ ceiling + 4 and within lanes/craters/tunnel volumes + margin), exact tunnel bores.
   Baked into each chunk's prop config (base64). ≤ 60k tris total.
6. **Vertex color realism** (no textures in v1): albedo from strata bands (wall height-noise
   bands), regolith dust on low slopes, scree at wall bases; **baked AO** (hemisphere raycast
   vs the collision BVH, ≥ 64 cosine-weighted samples/vertex, tunnel interiors near-black)
   multiplied into vertex color. The engine has no realtime shadows — AO is the depth cue.
   Materials: PBR metallic 0, roughness ~0.95, vertexColors on.
7. **Emit**: `content/props/lunar-rift-chunk-<i>.glb` + `.json` (category terrain,
   impactDamage 10, locked placements), guide-light strip props for tunnel interiors
   (small emissive planes, decor category, placed by the tool), `content/arenas/lunar-rift.json`
   (bounds box 640×640, floorY −20, ceilingY 74; spawns/flags/navGraph below; skybox
   `skyboxes/lunar-crater.webp` + existing sun), manifest entries.
8. **Self-check** (tool exits non-zero on violation): symmetry (every placement/spawn/flag/nav
   node has its twin within 1e-4), spawn/flag reachability (raycast down hits terrain within
   3u), nav connectivity (flag↔flag path exists), tunnel clearance (Ø ≥ 14 effective after
   noise), wire envelope, tri budgets.

### 7.1 Lunar Rift layout v1 (authored side = blue/south; twin generated)

- World: x,z ∈ [−320, 320]; highland top y=80; ceiling 74; kill-floor −20.
- **Blue crater**: center (0, −225), bowl r 60, floor y 4, three mouths: west (−58, −200),
  mid (0, −165), east (58, −200) — mouth floors ramp 4→0.
  - Flag base `flag-base-blue` at (0, −225), platform y 6, radius 16.
  - 5 pads arc at z ≈ −247: x ∈ {−24, −12, 0, 12, 24}, y 8, heading π/2 (facing mid/north).
- **Central crater**: center (0,0), r 90, floor −8 (the "large crater" symmetry point/hub),
  mouths N/S for the mid lanes + 4 tunnel portals (below).
- **Mid lane** (self-twin S-curve, width 34): (0,−165) → (14,−128) → (0,−90); twin half
  (0,90) → (−14,128) → (0,165).
- **West lane** (width 30–40, wall-noise varied): (−58,−200) → (−190,−120) → (−235,0) →
  (−190,120) → (−58,200). East lane = its 180° twin.
- **Tunnels** (straight, Ø15, bore center y 12): (−193,−95)→(−63,−63) and (−193,95)→(−63,63);
  twins on the east. Each connects a flank lane to the central crater.
- Scatter (via editor or tool): boulder props along lane edges (cover), crater rim rocks,
  2 team beacon props (emissive blue/red) at crater mouths, flag platform prop per base.
- Travel: flag-to-flag ≈ 450 u by lane — comparable to the shipped 536 u but with cover and
  rotation options. Lanes are 7–10 brawler-widths wide; tunnels ≈ 3.5.
